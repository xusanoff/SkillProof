## Phase 1 frontend: hh.uz-style header and navigation (plan)

The owner asked for hh.uz's information architecture: same structure, layouts and interaction patterns, but none of its brand (logo, name, red, illustrations, icons, copy). We keep the SkillProof name, the "Lapis & paper" tokens (D-015) and our own text. Compared with the Phase 0 frontend:

**Pages that change**

- Header (all pages). Phase 0 had logo, three nav links, language, theme and "Kirish". New layout: logo, then the search (query input with autosuggest, region select, "Qidirish" button). On the right: "Vakansiya joylash" and either "Kirish" or the avatar menu. The search sits inline from `lg`. Below `lg` the header is logo + search icon, and the icon opens the same form in a panel. The header search is hidden on the home page, which has its own larger copy.
- Mobile (< `md`): a fixed bottom navigation with Qidiruv, Saqlanganlar, Arizalar and Profil. HR users get role-specific items (Qidiruv, Vakansiyalar, Nomzodlar, Profil). On phones the language and theme controls move to the footer.
- Home hero: the main search (same component, larger) plus quick-filter chips: Masofaviy, Tajribasiz, Yarim stavka, IT, Stajirovka. The chips are links to `/vacancies?...`. The "how it works" and audience sections stay.
- New routes (localized "coming soon" pages until their phase): `/vacancies` (echoes `q`/`region`), `/candidate/applications`, `/candidate/saved`, `/candidate/results`, `/hr/vacancies`, `/hr/candidates`. `/settings` is real: `PATCH /auth/me` (name, interface language, timezone).

**Avatar menu**

- Candidate: Rezyumelarim → `/candidate/profile`, Arizalarim, Saqlanganlar, Natijalarim, Sozlamalar.
- HR: Vakansiyalarim, Nomzodlar, Kompaniya, Jamoa (Phase 1 requirement), Sozlamalar.
- Both menus end with "Chiqish". "Vakansiya joylash" goes to `/hr` for HR and to `/register?role=hr` for guests. Candidates don't see it.

**New components**

- `features/search`: `SearchForm` (GET form to `/[locale]/vacancies?q=&region=`, works without JS), `SuggestInput` (ARIA 1.2 combobox) and the `SuggestSource` interface. `emptySuggestSource` is the only source until Phase 2; wiring the real API means changing `defaultSuggestSource` in `features/search/suggest.ts`.
- Data files: `data/regions.ts` (Uzbekistan regions, ISO 3166-2 codes with uz/ru/en names; Phase 2 replaces it with the regions API behind the same `RegionSource` shape), `data/quick-filters.ts` (chip → query params) and `data/countries.ts` (ISO codes only, names from `Intl.DisplayNames`).
- `components/layout`: `SiteHeader`, `AccountMenu`, `MobileSearch`, `BottomNav`; `components/common/coming-soon.tsx`.

**Backend/API needed for Phase 2** (not built now): `GET /api/v1/search/suggest?q=&locale=` (vacancy titles, skills and companies, typed), `GET /api/v1/regions` (code and localized name), and saved vacancies (`GET/PUT/DELETE /api/v1/candidate/saved-vacancies[/{vacancy_id}]`). The vacancy list will need to accept `q`, `region`, `remote_type`, `experience_level`, `employment_type` and `profession_area` as query params; the chips already use these names.
